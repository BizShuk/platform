# 內容站候選評估 (2026-08-29)

## 問題

AdSense 審核看的是`匿名訪客打開網址看到什麼`。工作區有多個已上線網域,
哪一個真的能拿去送審並掛廣告?

## 判準

一個候選要同時滿足四項,缺一即不可行:

1. `公開` —— 匿名可讀, 沒有登入牆
2. `有量` —— 有足夠數量的實質內容頁面, 不是單頁工具
3. `原創` —— 內容是自己產的, 不是他人素材的彙整或衍生
4. `可注入` —— 有一個地方能把廣告 script 加進所有頁面

## 實測結果

以匿名 curl 檢查各網域首頁(2026-08-29):

| 網域 | HTTP | 大小 | 登入牆 | 判定 |
| --- | --- | --- | --- | --- |
| `fun.shuks.dev` | 200 | 30 KB | 無 | `可行` |
| `outfit.shuks.dev` | 200 | 68 KB | 無 | `有風險` |
| `bizshuk.github.io` | 200 | — | 無 | `頁數不足` |
| `vidnote.shuks.dev` | 200 | 1.4 KB | `有` | `不可行` |
| `feedback.shuks.dev` | 200 | 3 KB | 無 | `不可行` |
| `stock.shuks.dev` | 404 | 0 | — | `未部署` |

## 逐一評估

### 1. `fun` —— 首選

`984` 篇原創景點筆記, 涵蓋 13 個國家(taiwan / japan / france / poland /
indonesia / singapore / malaysia / philippines / netherlands / australia /
austria / belgium 等), 依「國家 / 城市 / 區域」分層。抽驗單篇內頁
`4.9 KB`、`INDEX` 頁 `165 KB`, 全部匿名可讀。

四項判準全過:

- `公開` —— 無登入, 深層內頁直接 200
- `有量` —— 984 篇遠超過審核所需的規模
- `原創` —— 個人實地筆記, 不是轉載
- `可注入` —— 站台由 `tools/mdserver` 供應, 它只有`一個` HTML 外框
  (`web/page.html`, 常數 `web.PAGE_TEMPLATE`)。改那一個檔就覆蓋全部 984 頁

題材是旅遊與餐飲, 屬正常可變現類別, 沒有政策上的特殊限制。

`唯一要確認的`:每篇筆記的實質文字量。抽驗的單篇約 4.9 KB, 尚可,
但若多數筆記只有店名與標籤而沒有敘述, 仍可能被判 `Low Value Content`。
送審前應抽樣 30 篇human-read 一遍。

### 2. `outfit` (FORME) —— 可行但有兩個風險

公開無登入, Next.js App Router, 廣告 script 加在 `app/layout.tsx` 即可全站生效,
注入難度最低。但:

- `工具型而非內容型` —— 它的核心是「上傳照片 → 試穿」的互動流程,
  頁面本體是 style catalog 與操作介面, 不是可閱讀的文章。
  這正是 `Low Value Content` 最常見的形態
- `圖片版權` —— 時尚造型圖若非自有或非授權, 是 AdSense 明確禁止的內容。
  送審前必須確認 `app/data/style-catalog.ts` 每一張圖的來源與授權

可作為 `fun` 過審之後再新增的第二個站, `不`建議拿它去做首次審核。

### 3. `bizshuk.github.io` —— 內容種子, 但頁數不足

已上線(實測 200), 但只有 `index` / `resume` / `surf` 三頁。
頁數遠低於審核所需。

`surf.html` 是以自己的 Uluwatu 照片做的 editorial magazine 頁 ——
這是`真正的原創內容`, 品質上是好種子。若要走這條路, 需要把它擴充成
一個有多篇文章的衝浪內容站, 工作量遠大於直接用 `fun`。

### 4. `vidnote` —— 不可行, 且有衍生內容疑慮

首頁只有 `1.4 KB` 且含登入元素 —— 審核員打開只會看到登入畫面,
`看不到任何內容`, 必然被拒。

更根本的問題:它的內容是`他人 YouTube 影片的摘要筆記`。
即使之後開放公開閱讀, 大量他人影片的衍生摘要在政策上屬於灰區,
不是適合拿來做首次審核的題材。

### 5. `feedback` —— 不可行

`feedback.shuks.dev` 是 widget 的收件端點, 回應 3 KB 的服務頁,
沒有任何供人閱讀的內容。它的角色是 API, 不是網站。

### 6. `stock` —— 未部署, 且屬 YMYL

網域回 `404`, 目前沒有上線。且金融投資內容屬 `Your Money or Your Life`,
Google 對這類內容的審核標準明顯更嚴, 不適合作為首次送審的題材。

### 7. `tools/ytdl` —— `絕對不要`

若曾考慮把它上線並掛廣告:AdSense 政策`明文禁止`協助侵犯版權的服務,
影片下載工具是被點名的類別之一。掛上去的風險是`整個帳號`停權,
不是單一站台被拒。

## 既有工作的衝突

`~/projects/social/google_ads/` 已有一份 `Google Publisher Tag (GPT)` 的
整合範例。`GPT 是 Ad Manager 的標籤, 不是 AdSense` —— 兩者的帳號體系、
審核路徑與版位設定都不同, 不應混用。

該範例用的是官方測試版位, 沒有產生無效流量的風險, 但它會讓人以為
「廣告整合已經做過了」。決定走 AdSense 之後, 應把它標為`參考用`,
實際上線一律走本 repo 的 `web/ads.js`。

## 結論

`用 fun 送審`。理由是它同時滿足四項判準, 而且注入點是單一 template ——
其餘候選各自缺至少一項, 補齊的成本都高於直接用 `fun`。
